## 3. 架构层性能预估

> 以下为基于项目技术栈（Go 1.22 + Gin + GORM + go-redis）的理论分析，需实测验证。

### 3.1 Gateway 纯转发层（/health 基准）

| 指标 | 预估值 | 依据 |
|------|--------|------|
| QPS (C=100) | 50,000 ~ 200,000 | Go HTTP 服务器 + Gin Recovery 中间件，无业务逻辑 |
| P99 延迟 | < 5ms | 纯内存操作，无 IO |

### 3.2 数据库读接口（Content/Task 列表）

| 指标 | 预估值 | 依据 |
|------|--------|------|
| QPS (C=100) | 500 ~ 3,000 | MySQL 单表分页 + GORM ORM 开销，受连接池限制 |
| P99 延迟 | 50 ~ 200ms | 包含 gRPC 调用 + DB 查询 + JSON 序列化 |
| 瓶颈点 | MySQL 连接池 + gRPC 调用 | 默认 MaxOpenConns=100，gRPC 无连接池 |

### 3.3 ES 搜索接口（/content/search）

| 指标 | 预估值 | 依据 |
|------|--------|------|
| QPS (C=100) | 100 ~ 800 | ES 查询延迟不稳定，取决于索引大小和 DSL 复杂度 |
| P99 延迟 | 100 ~ 500ms | ES 网络往返 + 分词 + 排序 |
| 瓶颈点 | ES 集群配置 + 索引优化 | 单节点 ES（开发环境）QPS 下限明显 |

### 3.4 Redis 缓存接口（/notifications/unread-count）

| 指标 | 预估值 | 依据 |
|------|--------|------|
| QPS (C=100) | 10,000 ~ 50,000 | Redis 单命令 <1ms，瓶颈在 gRPC 转发 |
| P99 延迟 | < 20ms | Redis GET + 计数器读取 |
| 瓶颈点 | gRPC 调用开销 | 应用层无缓存时每次请求都走 gRPC |

## 6. 已知限制与注意事项

1. **服务未启动**：当前 Gateway 未在本地运行，认证接口全部跳过，无真实压测数据
2. **gRPC 链路**：单 Gateway 压测不含下游服务真实处理时间（gRPC 连接未建立）
3. **数据量影响**：空库场景（帖子数=0）索引查询为全表扫描，实际有数据后可能更快（命中索引）也可能更慢（磁盘 IO）
4. **单机场景**：未包含多实例负载均衡、网络延迟、TLS 握手开销
